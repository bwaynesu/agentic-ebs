# Agentic EBS — 網頁 App

[English](README.md)

單機靜態網頁，資料存放於指定的本機資料夾。

## 執行方式

1. 線上版 <https://bwaynesu.github.io/agentic-ebs/>：使用 Chrome 或 Edge 開啟網址即可使用。

2. 本地端：clone 專案或直接下載 `App/` 資料夾

```
cd App
python -m http.server 8765
```

開啟 <http://localhost:8765>。File System Access API 需要 secure context。沒有 Python 時任何靜態伺服器皆可，例如 `npx http-server -p 8765`。

提醒：
- 瀏覽器限 Chrome 或 Edge（其餘不支援 File System Access API）
- 本工具不呼叫任何 API，需自行準備能在專案目錄下執行的 AI agent
- 任務卡累積二十餘張之前，估時分佈會偏寬是預期行為

## 第一次使用

- **建立任務資料夾**：在開發專案下新建一資料夾，並將其指定至頁首的「選擇任務資料夾」，內容會自動初始化。
- **關於任務資料夾建立位置**：建議放在開發專案中，多數 CLI agent 預設不存取工作目錄以外的位置；代價是記得將資料夾加進 `.gitignore`。
- **設定任務資料夾相對路徑**：需在設定頁中進行這項設定，用於告知 agent 如何找到任務資料夾。若填寫有誤，agent 會嘗試在專案中自行找尋該資料夾位置。
- **設定 Git 使用者名稱**：需在設定頁中進行這項設定，用於 agent 查找開發者過去的 log。

### 任務資料夾範例
| agent 執行目錄 | 任務資料夾位置 | 任務資料夾相對路徑 |
|---|---|---|
| `~/code/MyGame` | `~/code/MyGame/ebs-data` | `./ebs-data` |
| `~/code/MyGame` | `~/code/MyGame/docs/ebs-data` | `docs/ebs-data` |
| `~/code/MyGame` | `~/code/ebs-data` | `../ebs-data`（agent 需有上層目錄權限）|

## 任務頁面

左側欄用於顯示目前流程，中間是主要內容，目前進度要給予 agent 的 prompt 按鈕會上色。

- **開工計時應從撰寫需求描述開始**：釐清需求本身就是這張卡的工作。
- **需求越詳細，決定後面所有品質**
- **agent 會先停一次**：agent 釐清使用者需求後，它將列出假設與待釐清議題，確認後才續產解法與估時。
- **收尾仍要計時**：若將收尾落在工時區間外，未來 velocity 會偏樂觀。
- **被插斷直接開新卡**：舊卡計時會自動讓位，緊急卡完工後自動恢復。被會議或雜事打斷則不必暫停計時。

## 可將分析與實作拆不同 agent

任務各階段皆有獨立的規則書（`analyze-task.md`、`steps-guide.md`、`implement.md`），不同 agent 可接著執行後續流程。

- **留意 context**：走到拆解步驟卡階段時，分析 agent 已累積大量需求討論，若讓它接著實作，剩下的空間不多。
- **乾淨的 agent 更專注**：實作步驟卡各別獨立，可單獨領取。agent 不需讀整個討論過程，或理解前面的步驟卡。
- **判斷不被污染**：實作若走偏，回頭找分析 agent 討論時，它的看法還沒被實作細節帶著走。

## 工時計算

僅落在工作時窗內的部分才列入計算，夜間與休假計 0。時窗由設定頁的上下班時間、工作日與休息時段決定。

- **工作日曆可逐日覆寫**：且會回溯影響那一天已計入的工時與 velocity。
- **窗外時間唯一例外**：「開工」或「完工」正好按在窗外時，工具會問要不要計入。

以 09:00–18:00、午休 12:00–13:00 為例：

| 情境 | 算幾小時 | 確認 |
|---|---|---|
| 12:30 開工，18:00 完工 | 5（13:00–18:00）| 問 12:30–13:00 這半小時 |
| 11:00 開工，14:00 完工，中午沒關錶 | 2（11–12、13–14）| 不問，午休夾在中間 |
| 21:00 開工，23:00 完工 | 0 | 問這整段 2 小時 |
| 週五 17:00 開工，週一 10:00 才關錶 | 2（週五 17–18、週一 9–10）| 不問，週末夾在中間 |

- **只問該問的日子**：首頁只列出與計時區間重疊、且尚未確認的日子。
- **確認有先後**：先定當天實際的上下班時間，再裁決窗外時間。時窗一改，先前的裁決得重來。
- **未確認的代價**：不擋任何操作，但跨越這些日子的完成卡不會進入 velocity 統計池，卡片上會標示原因。

## 何時該修正計時區間

「時間紀錄」可以任意修改或刪除任何已結束的區間，亦可手動補新區間。進行中的那段無法編輯，需先按「完工」，改完再「重新開工」。

- **該修：紀錄錯誤**：忘了按開工、掛著過夜或過週末、誤按開工其實沒動工。
- **不該修：真實的膨脹**：開會、被同事叫住、臨時處理雜事。velocity 的存在目的正是捕捉這些膨脹。
- **判準標準：人在不在**：不在（睡覺、下班、忘了關錶）該修；人在、只是被別的事佔用，就留著。
- **事情大到值得追蹤**：替它開新卡，原卡自動讓位，時間各歸各的。

## 任務分類

- **分類的用途**：讓下次分析優先參考相近的舊任務，但不影響工時估算。
- **換成自己的詞彙**：設定頁的「② 分析規則」可改分類清單（做遊戲可換成 `gameplay`、`shader`、`level-design`）。
- **需維持固定詞彙**：別讓 agent 每次自由發明，同一概念若寫成 `frontend` 和 `front-end`，相近比對將會失效。

## Prompt

- **客製化 prompt**：使用者可在設定頁客製化 prompt。
- **升級不覆蓋客製化過的 prompt**：工具升級時，會逐檔比對 prompt 內容 hash，只有沒更動的會自動更新；使用者客製化過的 prompt 會在設定頁顯示有新版可替換。

## 關於語系

- **指示語言**：給 agent 的 prompt（`prompts/`）預設英文、且只有一份，但使用者可自行在設定頁修改 prompt 內容。
- **產出語言**：設定頁的「產出語言」填語言名稱即可（`繁體中文`、`日本語` 都行，留空視為英文），複製 prompt 時，將自動附加產出語言指示給 agent。
- **為何存放於資料夾中**：介面語言與主題存在瀏覽器，換電腦不跟著走；產出語言決定寫進資料夾的內容，換電腦也該是同一種，否則同一資料夾會長出兩種語言的歷史文件。
